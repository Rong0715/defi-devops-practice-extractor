Which DevOps practices do DeFi protocols actually use?

A practice-by-practice reading of the public repositories of influential, original Ethereum DeFi protocols. Every cell links to the file that produced it, pinned to a commit.

How common is each practice?

Share of protocols where the practice applies and was found. Practices that don't apply to a protocol (for example upgrade checks on an immutable one) are left out of that practice's denominator.

Said vs. run in CI

For each tool-like practice: how far did adoption get? “Mentioned” means only docs or comments. “Configured” means a config file or script exists. “Run in CI” means a workflow triggered by pushes or pull requests invokes it.

Whether a CI check is required before merging is a branch-protection setting held on GitHub's servers, not in the repository, so it cannot be observed here.

Where in the lifecycle is the effort?

For each protocol, the share of applicable practices found at each lifecycle stage, averaged across protocols. Stages group the ten dimensions: build → launch → governance → operate → assure.

Post-launch practices are the least visible in public repositories; a low bar there partly reflects what teams keep private.
